# Maximize Enfermagem

Plataforma que prepara enfermeiros brasileiros para aprovação em concursos públicos de enfermagem no Brasil. Monorepo com múltiplas aplicações.

## Arquitetura do Monorepo

| Diretório | O que é | Stack |
|---|---|---|
| `web-react/` | **Aplicação interna** — painel do usuário logado (questões, provas, métricas) | React 19 + Vite + MUI + TailwindCSS + TanStack Router + TanStack Query + Clerk (auth) |
| `nextjs-maximize-enfermagem/` | **Site público** — landing page, blog, conteúdo aberto | Next.js 16 + Sanity CMS (next-sanity) + TailwindCSS + PostHog |
| `studio-maximize-enfermagem/` | **Sanity Studio** — CMS para gerenciar conteúdo do site público | Sanity v3 |
| `api/` | **Backend** — source of truth para regras de negócio | NestJS + Prisma + PostgreSQL |
| `domain/` | **Domínio puro** — tipos e regras de negócio em TS (sem imports de framework) | TypeScript puro |
| `web/` | **App Angular (legado)** — cliente original, sendo substituído por `web-react/` | Angular + PrimeNG |

## Dev local

```bash
# Backend + banco
docker compose up -d          # Postgres
cd api && npm run start:dev    # NestJS em :3000

# App interna (React)
cd web-react && npm run dev    # Vite em :3001

# Site público (Next.js)
cd nextjs-maximize-enfermagem && npm run dev  # Next.js em :3002

# Sanity Studio
cd studio-maximize-enfermagem && npm run dev
```

Sem `institution` não há agrupamento. No front, a página `/exams/$examBoard/$examId` consome via `useExamConcursoProvasQuery`.
- **Página do concurso (nível 1):** `GET /concursos/:slug` (aceita UUID) é o payload canônico — status temporal (`open/future/past`) derivado no backend (`api/src/concurso/concurso-status.ts`), timeline agregada das provas, agregados/cargos só de provas `isNursingRelevant`, ordenados por salário desc. Um UUID que não bate em `Concurso` é tentado como `ExamBase.id` (fallback lazy que cria o vínculo na hora) — por isso a listagem `/exams` pode linkar `/concursos/$id` antes do vínculo popular.

Preenchida na criação/edição (criar-concurso e editar-concurso, campo "Data da prova") e é campo whitelisted na Fase 2 (retificação pode remarcar a prova).

- **Distribuição por matéria (bloco do nível 2):** `GET /exam-bases/:id/subject-distribution` (`@OptionalAuth`, `api/src/concurso/subject-distribution.service.ts`) — `mode: "actual"` p/ prova passada (questões da própria prova) ou `"historical"` p/ futura (união das `previousExams`, mesmo role+banca+instituição; `sourceExams` lista quais). `subject` null vira "Outros" se >5% do total, senão sai do cálculo (total reduzido junto — soma de counts = totalQuestions sempre). `userAccuracy` fração 0..1, mínimo 5 respostas senão `null`; `insight.topSubjects` = menor prefixo ≥50% (máx 3, sem "Outros"), `weakestRelevant` = maior `share × (1 - accuracy)`.

- **Scraper de documentos → criar concurso (admin):** `/admin/document-scraper` raspa uma página de concurso e a IA (GPT-4.1-mini) lista os documentos com `{ name, summary, url, publishedAt, kind }` — `kind` classifica (EDITAL_ABERTURA/RETIFICACAO/GABARITO/RESULTADO/CONVOCACAO/COMUNICADO/OUTRO), `summary` é uma frase do que é o documento. Backend: `POST /admin/scraper/documents` (`api/src/scraper/document-scraper.service.ts` — simplificação via cheerio, parse com jsonrepair). **Anti-bot em cascata** (`fetchHtml`): (1) `fetch` com headers de navegador; (2) se 403/429, warm-up de cookie (colhe `Set-Cookie` da origem, reenvia com `Cookie`+`Referer`); (3) `got-scraping` (imita headers/http2/TLS de Chrome — vence bloqueio por fingerprint de TLS); (4) **Playwright + stealth** (`renderWithBrowser`: Chromium roda o JS, junta o HTML de TODOS os frames — listas em iframe são comuns —, faz scroll p/ lazy-load e espera o desafio anti-bot limpar via `waitForChallenge`). Além do 403, o navegador também é acionado quando a extração estática vem com **0 documentos** (página renderizada por JS). got-scraping (ESM-only) e playwright são carregados via `esmImport` (import() escondido num `Function` p/ o webpack não empacotá-los — o build usa webpack; deploy precisa de `npx playwright install chromium` + libs do SO). ⚠️ **Cloudflare "Just a moment" (desafio gerenciado/Turnstile)** frequentemente NÃO cai no headless mesmo com stealth — `SCRAPER_HEADFUL=true` (janela real) ajuda no dev local, mas o modo gerenciado agressivo (ex.: Instituto Consulplan) barra até o navegador automatizado. Fallback definitivo: **colar o HTML** — `POST /admin/scraper/documents/from-html` (`{ html, sourceUrl }` → `scrapeDocumentsFromHtml`); o admin abre a página no próprio navegador (passa como humano), copia o fonte e cola no painel expansível da página do scraper. Alternativa p/ automação futura: FlareSolverr. ⚠️ Alguns WAFs fazem **geobloqueio** (só liberam IP BR) — o monitoramento futuro (roadmap 3) precisará sair por IP brasileiro. Na linha do edital, **"Criar concurso"** navega para a página dedicada **`/admin/criar-concurso`** (`?editalUrl=...&editalName=...` auto-extrai; sem params funciona standalone colando a URL do edital) — extração de edital COMPLETO via **`POST /exam-bases/extract-edital`** (`extractEditalConcurso`, em **duas fases**: (1) concurso + **etapas do certame** `{name, description, date}` (o cronograma) + TODOS os cargos com ficha compacta; (2) lotes paralelos de ~8 cargos transcrevem `requirements`/`description` **LITERALMENTE do edital** — nunca resumir/inventar; cada lote recebe só as janelas de texto onde os cargos aparecem (`buildFocusedText`) p/ recall, com retry em lotes de 4 p/ quem ficar sem; `isNursingRelevant` marcado pela IA; ~2min p/ edital de 60 cargos, timeout OpenAI 480s, PDF até 200 págs/400k chars; a extração roda como **query** cacheada por URL — nunca `mutate()` em useEffect, StrictMode engole a atualização) e form de revisão (Concurso / Etapas / Cargos expansíveis com enfermagem primeiro, match de banca com criação inline) → **`POST /concursos`** (ADMIN, `api/src/concurso/concurso-admin.service.ts`) cria o **Concurso SEM prova** (dono de `editalUrl` + janela + `resultDate` + **`etapas` Json**, via `findOrCreateConcurso` — mesma tupla do lazy-link, nada duplica quando a prova vier depois pelo wizard) + **cargos[]** com ficha completa (idempotente por `concursoId`+`role` case-insensitive) + **documents[]** (a lista raspada, passada da página do scraper via **sessionStorage** — `web-react/src/features/scraper/scrape-stash.ts` — pois é grande demais p/ query params; revisável no form). As **etapas do certame** têm `{name, description, date}` e **SÃO o Cronograma** do nível 1: quando há etapa com data, `buildEtapaTimelineSteps` (em `VerticalTimeline.tsx`) monta a timeline a partir delas (ordenadas por data; estado done/current/upcoming derivado de hoje; `keepUndated` mostra as sem data como "A definir"). **Curadoria anti-poluição:** editais listam ~20 micro-eventos — `condenseEtapas` funde pares "X — início/fim" num intervalo ("27/07 a 17/08/2026") e `isEtapaMajor` (regex por prioridade: homologação final > burocracia (recurso/retificação/boleto/nota/convocação...) > marcos (inscrições/prova/gabarito/resultado)) marca `major`; o `VerticalTimeline` colapsa as `major:false` (a etapa `current` sempre aparece) atrás de "Ver cronograma completo (N etapas)". **Anatomia:** `TimelineStep` carrega `startIso`/`endIso` (o componente formata) — cada etapa é um bloco-calendário (dia+mês; done = slate c/ badge ✓, current = cyan-700, undated = tracejado "—"), o trilho pinta cyan atrás das done (progresso do certame), e o marco corrente ganha wash cyan-50 + contagem regressiva ("termina em N dias"/"é hoje") — que substituiu o antigo chip âmbar do título do card; sem etapa datada, cai no cronograma derivado (`buildConcursoTimelineSteps` — inscrições/prova/resultado). Não há mais card "Etapas do concurso" separado. A IA de extração e os forms (criar/editar) preenchem a data de cada etapa. Agregados públicos seguem contando só cargos `isNursingRelevant`. Concurso sem prova **aparece** no nível 0 (`listConcursos` — bloco extra a partir do model `Concurso`) e no nível 1 (timeline dos campos próprios; card de cargo com `provaCount: 0`, sem link para o nível 2 — o front mostra "prova ainda não cadastrada"). **Documentos → timeline de Notícias:** model **`ConcursoDocument`** (`{title, summary, url, kind, publishedAt, sourceUrl}`, upsert por `@@unique([concursoId, url])` — idempotente e base do monitoramento futuro); persistido no `createFromEdital` e devolvido por `GET /concursos/:slug` em `documents[]` **mais recente primeiro** (`publishedAt` desc nulls last). A página do concurso (nível 1) tem **abas Cargos × Notícias** (`ConcursoTabs` no `index.tsx`, default Cargos); Notícias renderiza `ConcursoNews.tsx` — timeline vertical de documentos (data, chip de tipo, título linkado, resumo). **Manutenção da timeline (ADMIN, Fase 1 do monitoramento):** a `NewsAdminBar` (dentro do `ConcursoNews`, só p/ admin — `role==='ADMIN'` via `/auth/me`) tem **"Verificar novas publicações"** → `POST /admin/scraper/concursos/:id/documents/check` (`checkConcursoDocuments`: re-raspa `Concurso.documentsSourceUrl` pela cascata anti-bot, marca cada doc `isNew` comparando por URL; aceita `{ html }` colado p/ sites Cloudflare) → lista os novos com checkbox → **"Adicionar à timeline"** → `POST /admin/scraper/concursos/:id/documents` (`addConcursoDocuments`: upsert por `concursoId+url`) → invalida `['concurso']` e a timeline atualiza. `Concurso.documentsSourceUrl` (origem p/ re-raspar) + `documentsCheckedAt` (última verificação, mostrada na barra) são gravados no `createFromEdital`/no check e expostos no payload do nível 1. A ficha do concurso linka a **página oficial da organizadora** (`documentsSourceUrl`, com fallback ao `editalUrl`). O **colar-HTML é um caminho permanente, não afordância de erro**: a `NewsAdminBar` tem sempre dois botões — "Colar HTML" (secundário, abre o painel: passo-a-passo + "abrir página oficial em nova aba" + textarea → `check` com `{ html }`) e "Verificar novas publicações" (primário) — porque em site Cloudflare a raspagem sempre falha e esperar a cascata anti-bot (~40s) é desperdício; a mensagem de erro só aponta para o painel já existente. Cada linha da timeline mostra (só p/ admin) o **estado de leitura**: `ConcursoDocument.analyzedAt`/`changesAppliedAt` → selo "Não analisado"/"Lido"/"Lido · aplicado" (setados só na Fase 2; o sistema não re-lê o que já tem `analyzedAt`). E2E: `api/test/concurso-admin.e2e-spec.ts` (o ScraperModule NÃO está no app de e2e — puxaria BullMQ; o upsert é o mesmo de `createFromEdital`, já coberto). **Editar concurso (ADMIN):** botão "Editar" no header da página do concurso (só admin) → **`/admin/editar-concurso/:id`** (`editar-concurso.$concursoId.tsx`) carrega via **`GET /concursos/:id/edit`** (`getForEdit` — concurso + TODOS os cargos com ficha completa + `provaCount`) e salva via **`PATCH /concursos/:id`** (`updateConcurso`): atualiza campos do concurso + etapas + `documentsSourceUrl`, faz upsert dos cargos (id → update; sem id → create) e **remove os cargos SEM prova** que sumiram da lista (cargo com `provaCount>0` não pode ser removido aqui — é gerido pelo wizard de provas; o front desabilita o botão). O wizard de provas também aceita `?editalUrl=...&autoExtract=true` (extração por URL no `MetadataStep`). **Fase 2 (análise de conteúdo — feita):** cada documento (admin) tem **"Analisar alterações"** → `POST /admin/scraper/concursos/:id/documents/:docId/analyze` (`ConcursoDocumentAnalysisService.analyze`: baixa e lê o PDF via **`PdfOcrService`** (ver abaixo), monta um snapshot do estado atual `{concurso, cargos}`, e a IA — GPT-4.1-mini, prompt diff-aware — devolve só as mudanças que o documento **explicitamente** determina; marca `analyzedAt`). Retorna `changes[]` (`{id, target: concurso|cargo, cargoId, cargoRole, field, label, currentValue, newValue, evidence}`) — campos whitelisted (concurso: registrationStart/End, resultDate, editalUrl; cargo: vacancyCount, salaryBase, registrationFee, minPassingGradeNonQuota, workload, requirements, description, hasReserveList). **Documento `kind=EDITAL_ABERTURA` → análise completa da ficha:** o prompt de diff só reporta alterações explícitas (linguagem de retificação) e não transcreve textos longos, então nesse caso `analyze` roda também `ExamBaseAiService.extractFichasLiterais` (o extrator literal da criação, público) p/ os cargos `isNursingRelevant` e propõe `requirements`/`description` como mudanças normais (transcrição literal vence a entrada do diff no mesmo campo; valor igual ao atual não vira proposta) — cobre concurso criado via descoberta cujo edital só chega depois pela timeline. A análise também extrai o **cronograma** do PDF (etapas datadas) → `AnalyzeResult.cronograma` (null se não há ou é idêntico ao atual) **e o quadro de matérias por cargo** → `AnalyzeResult.syllabus` (`[{cargoId, cargoRole, groups:[{name, topics, questionCount, weight, maxScore}]}]`). **O quadro NÃO é transcrito no prompt de diff** (juntar diff + cronograma + transcrever N quadros num prompt só estourava a saída e saía errado): o prompt só devolve `syllabusCargos` (os NOMES dos cargos cujo quadro o documento traz) e, para cada um, a análise roda o **extrator focado compartilhado `ExamBaseAiService.extractSyllabusForCargo(text, role)`** (o MESMO da criação do edital — recorta a janela do cargo via `buildFocusedText` e reconstrói a tabela sozinho). `ScraperModule` importa `ExamBaseModule` (que exporta `ExamBaseAiService`). Só cargos **`isNursingRelevant`** (guard no loop) e só quando o quadro extraído **difere** do atual (replace total por cargo, não diff). O snapshot ainda inclui o quadro atual de cada cargo (`cargos[].syllabusGroups` só com os números) para o modelo apontar menos cargos. O `DocAnalysis` (no `ConcursoNews`) mostra o diff campo-a-campo com checkbox + evidência, um bloco "Cronograma proposto" (etapas com data, checkbox p/ incluir) **e um bloco "Quadro de matérias — <cargo>" por cargo** (matérias + números, checkbox por cargo) → **"Aplicar N itens"** → `POST .../apply` (`apply`: valida field contra a whitelist, coage o tipo, escreve no `Concurso`/`Cargo`; se `cronograma` aprovado, **substitui `Concurso.etapas`**; para cada `syllabus` aprovado, `applyCargoSyllabus` valida o cargo e faz **replace total do conteúdo programático por cargoId**; marca `changesAppliedAt`) → invalida `['concurso']` e o Cronograma/quadro do nível 1 se montam. **Decisão de produto: sempre revisar antes de aplicar, nunca auto-aplicar.** Cloudflare no link do PDF → erro amigável. **Leitura de PDF (OCR) — `PdfOcrService` (`api/src/pdf/`, `PdfModule`):** `pdfToText(buffer)` usa **Mistral OCR** (`mistral-ocr-latest`, `MISTRAL_API_KEY`) como primário — devolve as TABELAS como markdown alinhado (quadro de provas, distribuição de questões, cronograma param de vir embaralhados) e ainda lê PDF **escaneado** — com **fallback para `pdf-parse`** (local, achata tabelas) quando o OCR não está configurado, falha ou vem vazio. Usado tanto na **extração de edital** (`ExamBaseAiService.extractTextFromPdf`) quanto na **Fase 2** (`fetchDocumentText`); `PdfModule` é importado por `ExamBaseModule` e `ScraperModule`. Motivo: `pdf-parse` destruía o layout das tabelas e a IA errava o conteúdo programático. Roadmap: **(3)** monitoramento diário automático (re-raspar `documentsSourceUrl`, inserir só os novos via o upsert — precisa de IP BR e, p/ Cloudflare, FlareSolverr).
- **Gerenciar concursos + procurar novos (admin):** página **`/admin/gerenciar-concursos`** (`ConcursoDiscoveryService`, `api/src/scraper/concurso-discovery.service.ts`) lista TODOS os concursos (status temporal via `deriveConcursoStatus`; seção "Precisam de atenção" = `status !== past` ou `needsSourceUrl` = sem `documentsSourceUrl` nem `editalUrl`; "Concluídos" abaixo) e tem **"Procurar novos concursos"** → `POST /admin/scraper/discovery/search` raspa `pciconcursos.com.br/cargos/enfermeiro` (`parseCandidates`: 1 concurso por `a.noticia_desc` → `{ institution, uf, headline, newsUrl }`; `fetch` simples com headers de navegador, não é Cloudflare) e cruza com a base (`classifyCandidates`: dedupe por `Concurso.pciListingUrl` exato **ou** instituição normalizada + UF) → `new`/`exists`. Adicionar um `new` → `POST /admin/scraper/discovery/add` (**lazy**: (1) visita a notícia, IA gpt-4.1-mini extrai `bancaUrl`/`editalUrl`/ano/scope/cidade/janela; (2) `resolveConcursoLink` acha a **página oficial do concurso** — o "link do concurso da organizadora", **não** a home nem um agregador). **A busca do link usa a BUSCA WEB da OpenAI** (`callOpenAiWebSearch` → **Responses API** `POST /v1/responses`, tool `web_search_preview`, modelo `gpt-4.1` — override `OPENAI_WEBSEARCH_MODEL`) **+ VERIFICAÇÃO** (`findVerifiedConcursoLink`). O alvo é a **PÁGINA DE DOCUMENTOS do concurso na banca organizadora** (onde ficam os editais/retificações), **não** a home da prefeitura/banca nem a landing do concurso — o prompt (`WEBSEARCH_SYSTEM_PROMPT`) é enfático nisso e devolve `{officialContestUrl, organizerUrl}`. `cleanConcursoUrl` (pura, testada) rejeita agregadores (`AGGREGATOR_HOST`), tira tracking params e **rejeita home "pelada"** (domínio sem caminho — a home não tem editais). Cada candidata é então **confirmada** raspando-a (`countConcursoDocsAt` → `DocumentScraperService.scrapeDocuments`, cascata anti-bot + IA): só vira `documentsSourceUrl` a candidata que **de fato lista documentos** (`docCount > 0`); nenhuma confirma → `null` (fica "sem link — pegar manual", sinal visível em vez de salvar uma home errada). **Fallback** antes de verificar: link do concurso achado raspando o site da banca do 1º salto (`findConcursoLinkOnBanca`). Cria o Concurso stub via `findOrCreateConcurso` + `pciListingUrl` + cargo default "Enfermeiro". `needsSourceUrl = !documentsSourceUrl`. **`POST /admin/scraper/discovery/reextract`** (botão "Recorrigir links oficiais") roda **busca web + verificação** (usando órgão/UF/cidade/ano já salvos, sem re-raspar a notícia) sobre todos os concursos com `pciListingUrl` e só regrava `documentsSourceUrl` com um link **confirmado** (senão limpa → "sem link") — retorna `{processed, updated, stillMissing}`. É o "corrigir tudo de uma vez". Idempotente. `ScraperModule` importa `ConcursoModule`; `ConcursoDiscoveryService` injeta `DocumentScraperService`. `GET /admin/scraper/concursos` alimenta a listagem (devolve `closed` + `documentsCheckedAt`). **Frescor da verificação:** como a manutenção é majoritariamente manual, cada linha mostra há quantos dias o concurso não é verificado (`checkFreshness` em `web-react/src/features/scraper/check-freshness.ts` — puro e testado: dias de **calendário**, rótulos "nunca verificado"/"verificado hoje"/"há N dias", `stale` a partir de `STALE_AFTER_DAYS = 7` → âmbar; encerrado não mostra nada). A ordenação da lista é a **fila de manutenção**: `closed` → status temporal → **mais parado primeiro** (`staleRank`: nunca verificado antes de todos) → instituição. ⚠️ `documentsCheckedAt` é carimbado mesmo quando a raspagem volta com 0 documentos (bloqueio Cloudflare silencioso), então "verificado hoje" não garante que a origem foi realmente lida. **Botão "Atualizar concursos"** (`ConcursoUpdateService`, `api/src/scraper/concurso-update.service.ts`) roda o **monitoramento em massa**: o front pega os concursos **não fechados** e chama `POST /admin/scraper/concursos/:id/update` **um a um** (sequencial, com progresso ao vivo + relatório final). `updateOne` faz, por concurso, **Fase 1** (`checkConcursoDocuments` + `addConcursoDocuments` — adiciona os docs `isNew` à timeline) + **Fase 2** (lê os docs com `analyzedAt:null`, do mais antigo ao mais novo, `analyze` → `apply` **auto-aplicando TUDO** — decisão de produto: no fluxo em massa **não** revisa, ao contrário da Fase 2 por-concurso da aba Notícias) e devolve `{docsAdded, docsAnalyzed, itemsApplied, changes[]}`. **Encerrar concurso:** campo **`Concurso.closedAt`** (null = ativo) + botão **"Fechar/Reabrir"** por linha (`PATCH /admin/scraper/concursos/:id/closed {closed}` → `ConcursoDiscoveryService.setClosed`); o Atualizar **pula** os fechados e eles vão para "Concluídos". ⚠️ O Atualizar é **pesado** (por concurso: 1 raspagem + por doc OCR de PDF + IA) e o loop é sequencial no front — retomável (`analyzedAt` evita re-ler). ⚠️ A busca web do link é best-effort/mais lenta (~4-15s por concurso) e custa mais tokens; o reextract é sequencial. Testes: `concurso-discovery.service.spec.ts` (parser/dedupe) + `concurso-update.service.spec.ts` (orquestração, mocks — ScraperModule fora do app de e2e); página em `web-react/src/features/scraper/__tests__/gerenciar-concursos.test.tsx`.
